[ DESAIN PENYIMPANAN ] ------------------------------------------
Pilih SATU strategi rotasi:

  Opsi A : SINGLE FILE + ROTATE (RECOMMENDED)
    - File aktif    : /log/event.log
    - File lama     : /log/event.old (replace yang sebelumnya)
    - Cap ukuran    : 32 KB (tune sesuai sisa SD)
    - Saat append bikin file > cap:
        rename event.log -> event.old (overwrite),
        bikin event.log baru.
    - Pro : simple, FAT entry minim, append O(1).
    - Con : cari "10 baris terakhir" perlu seek dari akhir file.

  Opsi B : RING NUMBERED FILES
    - /log/00.log .. /log/09.log, masing2 max 10 baris.
    - Index file /log/idx.txt isi nomor file aktif.
    - Penuh -> increment idx, wrap ke 00 (overwrite).
    - Pro : "10 baris terakhir" = baca file aktif aja.
    - Con : 11 entry direktori, tiap file minimal 1 cluster
      (512 B) = boros space utk data yg cuma puluhan byte/baris.

  Opsi C : DAILY FILE
    - /log/YYYYMMDD.log, append seharian.
    - Butuh tanggal valid (ada NTP / RTC?).
    - Pro : human-readable, gampang cleanup manual.
    - Con : tergantung RTC; fragmentasi entry direktori jangka
      panjang.

Default rekomendasi : OPSI A.


[ FORMAT BARIS ] ------------------------------------------------
Satu baris = satu event, plain text CSV (bukan JSON, hemat byte):

    <epoch>,<index>,<uid_decimal>,<dev_class>,<flag>\n

Contoh:
    1731412345,7,123456789,LOCKER_A,SENT
    1731412410,3,987654321,LOCKER_A,PEND

Field flag:
    SENT  = sukses kirim ke log server
    PEND  = belum sempat kirim (buat re-upload nanti)
    LOCAL = event yg memang cuma utk SD (mis. boot, OTA_REQUESTED)

Estimasi ~40-50 byte/baris. 32 KB cap ~ 700 event = aman buat
beberapa hari pemakaian normal.

BUG SD Card
- kadang proses melambat dan device restart
  [MITIGASI v1] Dispatch event-log dibatasi 1 per loop (dulu semua flag
  send_log[] diproses sekaligus = transmit 3s + SD write numpuk dlm 1
  iterasi). Sekarang sisa flag diproses iterasi berikutnya, loop tetap
  responsif. + write gagal -> SD auto-disable (gak spam op lambat ke
  card mati). main_ethernet_.cpp send_log loop + sdf.cpp log_event.
  [BELUM TUNTAS] "device restart" kemungkinan besar RAM/stack pressure:
  RAM static 77.7% (~1.8KB sisa) + POST handler alok database_s
  new_db[30] (~420B) di stack + JsonDocument(heap) + String -> tabrakan
  stack/heap intermiten. Audit RAM = item terpisah (lihat FASE 4).
  CATATAN: WDT (lihat BUG #3) juga jadi jaring kalau "restart" ternyata
  dari loop yg nyangkut -> auto-reset <=8s, bukan beku permanen.
- jika sdcard tidak terdeteksi pada awal setup kemudian di loop sdcard di masukin program langsung stuck
  [FIX] Re-detect SD di loop() tiap 30s kalau sd_isnormal=false (card
  dicolok belakangan langsung kebaca tanpa reboot). Pakai
  sd_begin_coordinated(): kedua CS (W5100+SD) di-HIGH-kan dulu + clock
  SD_SCK_MHZ(4) -> SdFat nyerah cepat di slot kosong, bukan ngehang.
  Re-detect ditaruh SEBELUM gate cable -> tetap jalan walau Ethernet putus.
  CATATAN: kalau "stuck"-nya ELEKTRIS (MISO card murah gak tristate pas
  CS HIGH), ini gak nyembuhin -> verifikasi di HW; mungkin butuh resistor
  pull-up di MISO / level shifter. (sama akar masalahnya dgn BUG #3)
- [BUG #3] SD dicabut PAS RUNTIME (idle / loop jalan) -> system langsung
  stuck/hang. ROOT CAUSE: ELEKTRIS. Kartu yg setengah kecabut ngorup jalur
  SPI MISO yg dipakai bareng W5100; driver Ethernet W5100 muter di loop
  while(readSnSR/CR...) nungguin register yg gak pernah valid -> hang.
  [FIX/HANDLE] Gak bisa DICEGAH murni software (elektris). Tapi di-RECOVER
  pakai watchdog: wdt_enable(WDTO_8S) di akhir setup() + wdt_reset() di awal
  loop() & di dalam op jaringan transmit_eventLog (DNS/connect/drain).
  Hang > ~8s -> WDT fire -> auto-reset -> boot ulang (SD absen ditangani
  graceful, re-detect jalan). CATATAN: selama kartu MASIH setengah kecabut,
  boot ulang bisa ke-hang lagi di Ethernet.begin (MISO masih korup) -> bisa
  reset berulang SAMPAI kartu kelar dicabut / dipasang penuh; abis itu
  normal. Solusi tuntas = HW: pin card-detect (CD) buat tau kartu kecabut
  tanpa sentuh SPI, atau buffer/level-shifter di bus SD.
